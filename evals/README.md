# evals —— onboard 的测试方法

固化「陌生 agent 冒烟法」。每次改动 SKILL.md 后按此跑一遍，结果记录在本目录
（每次一个子目录或一份记录文件），防止 skill 悄悄退化。

## 冒烟 SOP

1. **陌生环境**：新会话、零背景，只给三样东西——本 skill（SKILL.md）、一份真实
   资料文件夹、一句角色卡（岗位 + 目标）。
2. **跑主流程**：理解目标从盘点走到带学；交付目标从盘点走到应用，中途不提示、不纠偏。带学阶段至少走完
   一个「现在要懂」项（含一次理解问题），并人为制造一次「问到拆解没覆盖的内容」
   验证回补回路。
3. **记录**：对话原样留存；`项目拆解包/` 产物原样归档。

## 判卷清单（逐项判 通过 / 失败，写明依据）

| # | 检查项 | 判什么 |
|---|---|---|
| 1 | 关键内容漏没漏 | 对照六清单（关键依赖 / 实操步骤 / 例外 / 限制风险 / 易混概念 / 新人障碍），抽查 3 项本资料里应能发现的上手关键点，是否出现在总览或路径 |
| 2 | 出处准不准 | 抽 5 条结论，逐条回到材料核对出处（路径:行 / 文件:页 / 工作表!单元格）是否真实支持该结论 |
| 3 | 标记诚实不诚实 | 推断是否标了「待验证」；矛盾是否并列呈现而非擅自裁决；说「看不到」前是否真做过检索；「待验证 / 缺失」为零时是否触发了交付前自检回查 |
| 4 | 产物数量守没守 B7 | 必产是否只有总览 + 路径；追加文件是否 ≤3 且各有触发理由；有没有为「完整」生成的空文件或空模板段 |
| 5 | 边界守没守 | 拆解阶段没改源文件；交付目标只在应用阶段改授权材料；密钥文件没读、材料没发外部；盘点脚本默认不落盘，拆解包在 Git 仓库被忽略；细节三档生效 |
| 6 | 带学形态对不对 | 理解目标默认开讲，交付目标默认完成产物即止；答错不卡流程、不重问原题；问到未覆盖内容时回补拆解 |
| 7 | 目标挂没挂钩 | 路径三档随角色卡目标裁剪，不是材料篇幅的均匀摘要；「现在要懂」项都带上手动作 |

## 资料集建议

至少三种类型各跑一遍：代码项目（真实仓库）、业务流程（内训/流程文档）、文职资料
（制度/手册文档堆）。同一资料、不同角色卡跑两遍，验证路径裁剪确实随目标变化。
