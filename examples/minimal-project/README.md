# minimal-project —— 最小可复制资料集

这是一份故意做小的混合资料：一个小型代码服务 + 一份业务文档，用于在没有真实项目时验证
onboard 是否正常工作。

## 用法

安装 onboard 后，新开一个 agent 会话，输入：

```text
用 onboard 分析 examples/minimal-project。
我是后端新人，目标是一周内能独立修改 src/service.js 的重试逻辑。
先给带出处的总览和学习路径，然后带我学。
```

## 预期行为（自检清单）

1. agent 识别到这是「代码系统」为主的混合材料，不追问、不卡流程；
2. 在资料夹生成 `项目拆解包/`，只含总览和学习路径（追加文件 ≤3）；
3. 总览里「重试次数」一类关键事实**挂代码行号出处**；
4. **能抓出矛盾**：`docs/business.md` 说"失败后重试 3 次"，代码实际重试 2 次——两说并列、不擅自裁决；
5. 结论有出处或标「推断，待验证」，没有的进待确认；
6. 全程只读：不改 `src/` 和 `docs/` 任何文件；
7. 沿路径讲第一个「现在要懂」项，讲完可用一个简短问题确认理解。

如果以上任何一条不成立，按 [evals/README.md](../../evals/README.md) 记录失败样例。

## 材料

- `package.json` / `src/index.js` / `src/service.js` —— 一个极小的重试服务
- `docs/business.md` —— 业务口径（与代码有一处故意不一致）
